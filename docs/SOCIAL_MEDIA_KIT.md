## One-line description

SyntraLang is an experimental, intent-oriented language foundation exploring explicit goals, effects, uncertainty, and governance for cognitive systems.

## Short description

SyntraLang is an independent Rust language project exploring how intent and cognitive-system constraints can become inspectable language structures. It currently includes a Unicode-aware lexer, an initial borrowed parser/AST, source-aware diagnostics, early semantic verification, and invocation-coordination foundations. It is pre-alpha and does not yet provide a complete compiler or execution runtime.

## Announcement post

Introducing **SyntraLang** — an independent language foundation exploring how software can express not only what it computes, but also the intent, goals, uncertainty, effects, and governance surrounding that computation.

The project is being built in Rust with an emphasis on explicit contracts, source provenance, and security boundaries. The current pre-alpha foundation includes a lexer, initial parser and borrowed AST, diagnostics, early semantic verification, and invocation coordination.

This is early engineering work, not a finished language or runtime. The focus is on getting the foundations right.

Explore the code and follow development:
https://github.com/gd2bk1ng/syntra_lang

## Developer-focused post

SyntraLang is an open-source Rust language experiment with a borrowed source/token/AST pipeline, recursive-descent parser, recoverable diagnostics, initial semantic checks, and registry-qualified invocation identities.

Current status: pre-alpha. No complete compiler, interpreter, or capability-enforcing execution backend yet.

Repository: https://github.com/gd2bk1ng/syntra_lang

## Sharing guidelines

- Link to the canonical `main` branch or a tagged release, not an experimental branch.
- Say "exploring", "designed for", or "planned" when describing future capabilities.
- Do not claim consciousness, autonomous agency, secure sandboxing, production readiness, a completed runtime, or formal verification.
- Do not use CI badges as evidence that a particular untested branch passed; link to the actual workflow run.
- Prefer a concrete code example or test-backed feature over broad marketing language.

## Visual identity

Use the name **SyntraLang** consistently. The Rust package/crate name remains `syntra_lang`. Keep the logo and social preview simple and legible; avoid implying that unimplemented features are shipping.
